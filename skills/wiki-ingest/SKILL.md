# wiki-ingest：笔记摄入

读取源笔记，写入wiki，交叉引用一切。一个源笔记通常触及5-15个wiki页面。

**语法标准**：使用Obsidian Flavored Markdown。Wikilinks用`[[页面名]]`，callouts用`> [!type] 标题`，嵌入用`![[文件]]`，属性用YAML frontmatter。

---

## 单文件摄入

触发：用户指定一个vault中的笔记文件让AI摄入。

步骤：

1. **读取**源笔记，完整读取，不要跳读。源笔记位于vault中wiki/以外的任意目录（如`4. 团队管理/`、`5. 工作记录/`等）。**源笔记是只读的，不得修改。**
2. **讨论**关键要点。问用户："需要我重点关注什么？颗粒度多细？"如果用户说"直接摄入"则跳过此步。
3. **分发到对应子目录**，按以下规则创建或更新wiki页面：

   | 内容类型 | 目标目录 | 示例 |
   |----------|----------|------|
   | 人物信息（团队成员、候选人、关键联系人） | `wiki/人物/` | 张伟.md、候选人-李明.md |
   | 团队结构、组织架构、业务板块 | `wiki/组织/` | 安全本部.md、治理本部.md |
   | 项目与专项 | `wiki/项目/` | 乘客安全专项.md |
   | 技术系统、平台、工具 | `wiki/系统/` | 风控引擎.md |
   | 业务知识、流程、规则 | `wiki/业务/` | 安全治理流程.md |
   | 框架、方法论、理念 | `wiki/概念/` | OKR方法论.md |
   | 故障、事故、重要事件 | `wiki/事件/` | 2026-03-15线上故障.md |
   | 技术选型、组织调整、优先级取舍 | `wiki/决策/` | 策略引擎选型.md |
   | OKR、KPI、指标定义、里程碑 | `wiki/目标/` | 安全事件率.md |
   | Runbook、审批链路、应急响应流程 | `wiki/流程/` | 线上故障响应.md |

   一个源笔记可能同时产出多个子目录下的页面。

4. **交叉引用**。在每个新建或更新的wiki页面中，用`[[wikilink]]`链接到其他相关wiki页面。
5. **标注来源**。每个wiki页面底部用wikilink列出源文件（Obsidian中可直接点击跳转）：
   ```markdown
   ## 来源
   - [[4. 团队管理/班子建设追踪]]
   - [[5. 工作记录/周会纪要-0506]]
   ```
6. **更新`wiki/index.md`**。为所有新页面添加条目。
7. **更新`wiki/hot.md`**，写入本次摄入的上下文。
8. **追加`wiki/log.md`**（新条目在最顶部）：
   ```markdown
   ## [YYYY-MM-DD] ingest | 源笔记标题
   - 源文件：`4. 团队管理/班子建设追踪.md`
   - 页面创建：[[张伟]]、[[安全本部]]
   - 页面更新：[[组织架构总览]]
   - 关键信息：一句话概括本次摄入的新增知识。
   ```
9. **检查矛盾**。如果新信息与已有wiki页面冲突，在两个页面上都添加`> [!contradiction]` callout。

## 批量摄入

触发：用户指定多个文件或说"批量摄入"。

步骤：

1. 列出所有待处理文件，确认后再开始。
2. 逐个按单文件摄入流程处理。各源文件之间的交叉引用推迟到步骤3。
3. 全部处理完毕后，做一轮交叉引用检查，寻找新摄入源文件之间的关联。
4. 最后统一更新index、hot cache和log（不是每个文件更新一次）。
5. 报告："已处理N个源文件。创建X个页面，更新Y个页面。以下是发现的关键关联。"

批量摄入交互较少。超过30个源文件时，每处理10个与用户确认一次进度。

---

## Context Window纪律

token预算很重要。摄入时遵循以下规则：

- 先读`wiki/hot.md`。如果其中已包含相关上下文，不要重读完整页面。
- 读`wiki/index.md`查找已有页面，避免重复创建。
- 每次摄入最多读3-5个已有页面。如果需要读10+个，说明你读得太广了。
- 用局部编辑修改已有页面，不要为了改一个字段而重读整个文件。
- wiki页面保持精简，100-300行为上限。超过300行就拆分。

---

## 矛盾处理

当新信息与已有wiki页面矛盾时：

在已有页面上添加：
```markdown
> [!contradiction] 与[[新源笔记]]冲突
> [[已有页面]]说X。[[新源笔记]]说Y。
> 需要核实。检查日期、上下文和原始信息。
```

在新信息对应的页面上引用：
```markdown
> [!contradiction] 与[[已有页面]]矛盾
> 本次摄入的信息说Y，但wiki中已有信息说X。详见[[已有页面]]。
```

不要默默覆盖旧结论。标记出来，让用户决定。

---

## 不要做的事

- **源笔记是只读的。** vault中wiki/以外的所有文件都不得修改。
- 不要创建重复页面。创建前必须检查index和搜索已有页面。
- 不要跳过log条目。每次摄入必须记录。
- 不要跳过hot cache更新。它是让后续session保持快速的关键。
- 不要臆造信息。wiki页面中的内容只能来自源笔记，不得编造。
